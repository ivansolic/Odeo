## Header

Goal: a deterministic, dependency-free check that WARNS when a generated document's prose region reads as a different supported language than the project's effective `output_language` setting, without ever failing anything, and without firing on German prose that legitimately embeds English technical terms.

Serves: PRD-001's outcome, "a non-English PM/builder runs the full Odeo lifecycle and every artifact they read is in their chosen language, after a single setup choice, while the codebase, tooling and collaboration stay language-neutral." This story covers R7's MECHANISM; the invocation half ships in the deferred story named in gate decision G2, so R7 is not closed by this story alone. It also closes the hole USR-005 left on the record: USR-005 design decision 13 and its Risk 1 both say AC1's "the body is German" is not closable by any script in this repo and that the detector is USR-006. This story builds that detector, as a WARNING and never as a gate, because a gate on a heuristic invites building to the gate (USR-005 design decision 13, kept).

Architecture context (inherited, not redecided):
- Deterministic logic lives in `bin/*.sh`, each with a self-contained `tests/*.test.sh`. House style: `set -uo pipefail`, `usage()` on stderr, exit 0 clean / 1 violation / 2 usage error, `mktemp -d` plus `trap` fixtures, `LC_ALL=C` for any character class so locale collation cannot widen it (`bin/language-guard.sh:48-59`).
- Portability floor: macOS bash 3.2.57 and BSD userland. No associative arrays, no `mapfile`, no `grep -P`, no GNU-only `sed -i`, no `awk` `gensub`.
- The setting is one line, `output_language: <code>`, code in `en de hr fr`, precedence project > global > `en`, resolved by `bin/resolve-language.sh` (USR-002, shipped). `bin/language-status.sh` takes the CODE from the resolver rather than re-deriving it, so the two can never disagree (`bin/language-status.sh:61-64`); this plan reuses that pattern exactly. Both read the global config from `CLAUDE_GLOBAL_CONFIG`, defaulting to `$HOME/.claude/CLAUDE.md`, which is what makes hermetic tests possible.
- `bin/language-guard.sh` (USR-001) is the `[E]` machine-surface gate. It never reads prose below the frontmatter's closing `---` and it exits 1 on violation. It is untouched by this plan.
- Advisory `bin/*.sh` scripts exist here alongside gates, and the repo distinguishes them in the HEADER COMMENT rather than in the filename: `bin/session-end-check.sh:3-8` is "an advisory end-of-session sweep ... Advisory only: it prints, it never blocks, and it ALWAYS exits 0", and `bin/focus-check.sh:20-21` also always exits 0. `bin/boundary-check.sh` and `bin/coverage-check.sh:54` are the ones that exit non-zero. This plan follows the advisory precedent (design decision 2).
- Guardrails are tagged `[E]` enforced / `[I]` instructed in `AGENTS.md`, which is their single source of truth; skills and agents REFERENCE them. `AGENTS.md` is NOT copied to a user machine by `install.sh`, which is why `global/CLAUDE.md` is the delivery vehicle for a rule that must reach installed users (USR-005 design decision 11).
- `install.sh:82-86` copies every `bin/*.sh` to `~/bin`, so a new script reaches user machines with no installer edit.
- Mechanical invariants over the system's OWN files live in `docs/invariants.md` + `bin/skills-lint.sh` + `tests/skills-lint.test.sh`, maintained doc -> RED -> GREEN.
- Dev rigor: TDD-lite, plus this repo's house rule that a coverage claim is proven by MUTATION before it is written (`CLAUDE.md`, `.claude/tasks/lessons.md:14`), and that a negative claim needs an instrument proven to give a positive (`.claude/tasks/lessons.md:15`, and its 2026-08-13 refinement: prove the instrument BEFORE reporting, and run byte-class probes from a script file, never as an inline shell string).

Constraints (verbatim from the story, plus the inherited ones):
- "With the effective language German and a generated body whose prose region is detected as predominantly (more than half) a language other than German, a warning is shown that names the artifact."
- "With a correctly German body, no warning is shown."
- "The check never hard-fails: its exit stays 0, it only warns."
- "A body of German prose that embeds English technical terms (API names, code) does not trigger the warning."
- "Verification note (this repo): best-effort language detection over the prose region only (exclude code blocks and frontmatter); tests with one matching and one mismatching sample."
- Inherited: no em dashes or en dashes in any text (lint C7); code comments English only; the full test suite and `bin/skills-lint.sh` stay green; every committed path stays classified for `publish-guard`; no new runtime dependency (a language-detection library would be an ADR-level change, see Risk 12).

## Design decisions (resolved, so the builder does not guess)

1. **A NEW standalone script, not a flag on `language-guard.sh` and not a check inside a skill.** Three reasons in order of weight. (a) Exit-code semantics: `language-guard.sh` is the `[E]` gate whose contract is "exit 1 = a machine surface is dirty". A soft warning folded into it either changes that exit (turning a heuristic into a blocker, which AC3 forbids) or adds an output channel its callers do not read, and either way a caller seeing exit 1 could no longer tell a hard violation from a guess. (b) It would re-stale USR-001's reviewed 19-case surface for zero functional gain. (c) A skill-only check cannot be tested, and the story asks for tests over two samples.

2. **The script is named `bin/prose-language-check.sh`, following the `session-end-check.sh` precedent.** v1 named it `prose-language-warn.sh` on the premise that "every existing `*-check.sh` here is a gate that refuses". That premise is FALSE and this repo contains the opposite precedent: `bin/session-end-check.sh:3-8` describes itself as "an advisory end-of-session sweep ... Advisory only: it prints, it never blocks, and it ALWAYS exits 0", which is this script's semantics verbatim under a `-check.sh` name, and `bin/focus-check.sh:20-21` also always exits 0. Only `boundary-check.sh` and `coverage-check.sh:54` exit non-zero. So `-check.sh` here means "a check", spanning advisory and gating, and the distinction is carried by the HEADER COMMENT, not the filename. Three consequences, all deliberate: (a) the name is PRD-001 R7's own word, so the artifact and the requirement match and no mapping note is needed; (b) the advisory semantics are stated in the first lines of the header comment, in the same voice as `session-end-check.sh:5-8`, because that is where this repo puts them; (c) the one divergence from `session-end-check.sh` is stated there too: it exits 0 even when it breaks, because a Stop hook must never trap a session, while this script exits 2 on a malformed invocation (G1), because an agent that mistypes the invocation must learn the check did not run rather than read silence as a pass. The word "warn" survives where a reader actually meets it: the `WARN` status token and the second report line.

3. **The rule is `[I]`, and the plan says why calling it `[E]` would be a lie.** `[E]` here means a mechanism physically stops the thing (exit code, tool restriction, git hook). This script's exit is 0 for every possible document content, by contract, so it stops nothing: a mismatched document commits, merges and ships exactly as before. What exists is a mechanism plus an instruction to run it. One `[E]`-adjacent fact stated without overstating: the script IS deterministic and tested, so "the warning fires on a mismatching body" is tested behavior. Tested is not enforced.

4. **The prose region is an exclusion pipeline, declared once as C1, and every exclusion has a reason tied to a shipped rule.** The load-bearing one: ATX headings are EXCLUDED, because `AGENTS.md` Guardrails 7 requires structural labels, including headings that appear as literals in a format doc or a skill's document shape, to stay ENGLISH in a localized document. Counting them would push every correctly localized document toward "predominantly English", a false positive built into the design. Table rows are excluded for the same class of reason (their cells are predominantly labels, paths and commands). Frontmatter, fenced code, inline code spans, link targets and URLs are excluded because the story says so or because they carry identifiers rather than prose. That is **SEVEN** exclusions, and all seven are named wherever the region is described, including Task 4(a)'s canonical bullet. 4-space-indented blocks are deliberately NOT excluded: in this repo's markdown, deep indentation is overwhelmingly list continuation, which IS prose, so excluding it would delete more prose than code; the cost is that a document using indented code blocks feeds those tokens to the tokenizer, where they match no list and are ignored.

5. **Detection is function-word frequency over a closed, per-language list. AC4 survives on three named mechanisms, NOT "by construction", and v1 overclaimed here.** What is true: a BARE single-word English technical noun (`API`, `Endpoint`, `Token`, `Cache`, `Webhook`, `Timeout`) is in no list, so it scores zero English hits, and that is the common shape of an embedded technical term. What v1 got wrong, measured against the tokenizer this plan specifies (every byte that is not an ASCII letter becomes a newline, so `-`, `/`, `.` and spaces all split): German technical compounds and English multi-word phrases DO leak English function words. `for-Schleife` yields `for`; `if-then-else` yields `if` and `then`; `Read-Only-Modus` yields `only`; `Out of Memory` yields `out` and `of`; `as a Service` yields `as`; `not found` yields `not`. And "the English list contains no nouns at all" is false: `can` is also an English noun, and `out`, `over`, `under`, `some` are content words in some uses. So AC4 rests on: (a) the seven region exclusions, which remove the DENSE English where such phrases overwhelmingly sit in this repo's documents; (b) `MIN_HITS=12`, so a leak of two or three tokens cannot decide anything; (c) the strict-majority rule against the single best rival, so a German document needs the leak to EXCEED its German count to flip. The `en=0` assertion on `PRD-905-api-quota.md` remains valid and worth asserting: it proves a property of THAT FIXTURE (whose English terms are deliberately bare single-word nouns and whose dense English sits in excluded regions), paired with a control proving those same words DO count as plain prose. It is not evidence of a general guarantee, and nothing in this plan claims it is (`.claude/tasks/lessons.md:14`).

6. **The lists are pairwise DISJOINT, and the HIGHEST-FREQUENCY cross-language homographs are excluded from ALL lists.** The disjointness rule is the correctness core and it is machine-checked (C2's invariants). Without it the check is worse than useless: German `an in am was also will man hat war` are all English words; French `je se ne si` are all Croatian words; English `to do on no` are all Croatian words; French and German share `des du`. Any of those in a list would score hits for the wrong language on correct prose. The four language CODES are also excluded, because this system's own documents discuss them as literal codes. And the English interrogatives that Guardrails 7 mandates as English structural labels in reviewer output templates (`what why how where who`, as in `**What:**`) are excluded.
   **Accepted residue, named because v1's absolute claim was false.** Seven lower-frequency cross-language homographs DO remain: `im` (WORDS_DE, and the Croatian dative clitic); `te` and `ta` (WORDS_HR, and French `te`, `ta`); `but` and `or` (WORDS_EN, and French `le but`, the conjunction `or`); `die` and `den` (WORDS_DE, and English content words). They are not pruned, and the reason is directional: every removal costs signal on the language whose list loses the entry, and English signal is exactly what AC1's mismatch detection depends on, so trading it away to remove a few hits of noise is the wrong trade. The residue is bounded by the same two mechanisms decision 5 leans on, and it is unenforceable anyway: "is this token also a word in another language" has no mechanical oracle in a dependency-free bash repo, which is precisely why the plan machine-checks DISJOINTNESS (decidable) and writes the residue down (not decidable).

7. **All four lists are ASCII-only, on purpose, which removes an entire class of encoding bug.** Function words carrying diacritics are left out; each language has 50 or more ASCII-only function words, which is plenty of signal. Consequence, stated so nobody "improves" it: the tokenizer splits on non-ASCII-letter bytes, which chops a diacritic word into fragments, and since single-character tokens are excluded from every list and no entry is a plausible fragment, those words are silently ignored rather than miscounted. Simple lowercase ASCII folding is therefore sufficient, and an ALL-CAPS diacritic word is a miss we accept.

8. **The threshold is a NUMBER and it is two clauses, not one:** warn if and only if the single best rival language holds MORE THAN HALF of the counted function-word occurrences, AND the total counted occurrences are at least 12. "Single best rival" is chosen over "all others combined" because the warning must NAME the detected language, and the combined reading fires on a genuinely multilingual document where no single other language dominates, which is noise. The 12-hit minimum exists because below it a single stray sentence decides the verdict; 12 is the smallest total at which a strict majority (7 of 12) cannot come from one short quoted line. Both numbers live in the script as named constants with exactly one assignment site each, both are stated in `AGENTS.md`, and group H asserts the one-site property mechanically. Each clause gets one isolating test case, per `knowledge/plans/a-reviewed-contract-is-not-a-correct-contract.md`.

9. **The expected code always comes from `resolve-language.sh`, never from a flag.** The script takes `<project-dir> <file> [<file>...]`, resolves the code exactly as `language-status.sh:61-64` does (invoking the resolver, passing `CLAUDE_GLOBAL_CONFIG` through), and never re-implements the precedence. A `--expect <code>` escape hatch was considered and DECLINED: it would create a second source of truth for the effective language, and a caller who wants a different code can point at a different project directory, which is what the tests do.

10. **Exit 0 for every document content; exit 2 only for a malformed invocation.** Per G1. Exit 1 is produced by nothing, ever.

11. **Nothing invokes it automatically, and the rule reaches its readers by reference rather than by editing sixteen files.** The canonical `[I]` rule goes into `AGENTS.md` Guardrails 7, which the five prose-generating skills, `skills/build/SKILL.md` and all ten agent definitions are already mechanically required to POINT AT (lint C13, shipped by USR-005). So a new bullet in section 7 propagates to every generating surface by reference, with no edit to those sixteen files. One sentence is added to `global/CLAUDE.md`, because that file reaches an installed user's global config while `AGENTS.md` does not. Wiring the invocation is G2's deferred story.

12. **No NEW lint invariant, but C5's SCOPE is widened, and v1's flat "no lint change" was the wrong answer.** There is still no C14 asserting that a bullet mentions the script (that would grep for presence, not meaning, and would buy nothing C13's pointer does not already buy). What v1 missed: C5 ("every referenced `*.sh` exists") scans only `skills/` and `agents/` (`bin/skills-lint.sh:58`), so the two files this story edits to NAME the script, `AGENTS.md` and `global/CLAUDE.md`, are outside it. Since Guardrails 7 is the single source sixteen surfaces point at, a later rename of the script would leave all sixteen instructing agents to run a nonexistent file with every gate green. Task 5 widens C5 to those two files. It is deliberately NOT widened to `docs/`: `docs/plans/` and `docs/decisions/` are HISTORICAL RECORDS that name the scripts as they were called at the time, so checking them against the current tree would demand that records be rewritten after every rename, which is the opposite of what a record is for.

13. **The USR-005 letter-class defect is FOLDED IN, and this is why it belongs to USR-006.** `tests/localized-prose.test.sh:96-97` counts non-ASCII BYTES with `$'[\200-\377]'` while three surfaces claim LETTERS. Three wrong-reason passes were demonstrated (a curly apostrophe, box-drawing inside a code fence, an NBSP), each with the German fully transliterated. It belongs here for three converging reasons. (a) OWNERSHIP: "what counts as a letter of language X" is the definitional question this story exists to answer, and a repair elsewhere would be a second, uncoordinated answer. (b) SUBJECT: the broken assertion sits on `PRD-901-login.md`, which is this story's German matching sample. (c) DEFECT CLASS: one of the wrong-reason passes was caused by a code FENCE, which is one of the regions C1 must exclude. What is NOT shared is the REGION: the test asks "does anything below the frontmatter carry a non-ASCII letter" (a fixture-shape tripwire whose correct region is everything below the closing `---`, including the H1) while the script asks "what language is the prose" (a narrower region that excludes headings). Keeping those regions separate is correct, and it is written down so a later reader does not "unify" them into a shared helper that would answer the tripwire's question wrongly. The class literal has exactly ONE site after this plan (Task 1's helper); the script defines no letter class at all, because its lists are ASCII-only.

14. **The replacement letter class is `$'[\303-\305][\200-\277]'`, and the plan records how it was verified, because a previous prescription in this exact place was itself the defect.** Measured on both grep binaries present here (the `ugrep` on PATH and `/usr/bin/grep`): both return 2 on a six-line probe containing an umlaut line, an ASCII line, a Croatian-caron line, a U+2019 line, an NBSP line and a TAB line, where 2 is the correct letter count. An `awk` byte test returns 2 as well, so the result does not depend on which grep is installed. IMPORTANT INSTRUMENT NOTE for whoever re-verifies this: run the probe from a SCRIPT FILE. An inline `$'...'` pattern passed through a tool command layer can arrive mangled and then silently matches nothing, which produced two false findings during this plan's own gate and is why `.claude/tasks/lessons.md` gained the 2026-08-13 entry.

15. **Every mutation proof in this plan is undone BY HAND, never with git, and this is a hard rule because v1 shipped a task-destroying command.** In each task the mutation proofs run inside the task, BEFORE its commit, so every file being mutated is UNCOMMITTED at that moment. `git checkout -- <path>` therefore reverts to HEAD and destroys the task's own work (v1's Task 1 said exactly that, which would have wiped the new helper, cases R1 and R2 and the class fix in one command). The rule for Tasks 1, 2, 3 and 5: mutate the ONE named site, run the named suite, observe the named case red, then re-edit that one site back by hand, and prove the undo by re-running the suite to green. `git checkout`, `git stash` and `git restore` are forbidden as undo mechanisms anywhere in this plan. This is safe precisely because every mutation named here has exactly one edit site.

## Contracts (declared once, referenced by name)

### C1: the prose region
- Kind: input-filtering mechanism (a document-to-text transformation)
- Declaration: the PROSE REGION of a file is produced by applying, in this order:
  1. **CR strip.** Every line has trailing CR removed before any test (`tr -d '\r'`, as `bin/language-guard.sh:79-80` does), so a CRLF document behaves identically.
  2. **Frontmatter drop.** If line 1 is exactly `---`, drop line 1 through the next line that is exactly `---`, inclusive, and KEEP everything after that closing delimiter. If line 1 is `---` and no closing `---` exists, the region is EMPTY. If line 1 is not exactly `---`, nothing is dropped. Same delimiter model as `bin/language-guard.sh:82-90`, deliberately: one model for the guard and the checker.
  3. **Fenced code drop.** A line whose first non-whitespace run is three or more backticks OR three or more tildes toggles fence state. The opening line, everything inside, and the closing line are dropped, and the line AFTER the closing line is back outside the fence. An unterminated fence drops to EOF.
  4. **Heading drop.** Outside a fence, a line matching an ATX heading (up to three leading spaces, then one to six `#`, then a space or end of line) is dropped whole, and ONLY that line.
  5. **Table-row drop.** Outside a fence, a line whose first non-whitespace character is `|` is dropped whole, and ONLY that line.
  6. **Inline code-span deletion.** On each surviving line, delete every SHORTEST backtick-delimited span, repeatedly, so text BETWEEN two spans on one line survives. An unpaired trailing backtick deletes nothing.
  7. **Link-target deletion.** Delete every `](...)` group up to its first `)`, keeping the link TEXT, which is prose.
  8. **URL deletion.** Delete every run beginning `http://`, `https://` or `mailto:` up to the next whitespace, `)` or `>`.
  Steps 6, 7 and 8 run in that order. Everything that survives is the prose region.
- Produced by: Task 2
- Consumed by: Task 3, Task 4
- Invariants: the region never includes any byte from the frontmatter block, from inside a fence, from a heading line, from a table row, from an inline code span THAT OPENS AND CLOSES ON ONE LINE, from a link target or from a URL; NO exclusion consumes more than the construct it names (a heading drops one line, a table row drops one line, a closed fence drops only through its closing line, a closed frontmatter block drops only through its closing `---`, a code span deletes only up to its own closing backtick, and NO deletion ever crosses a line break); the transformation is content-only and never rewrites the file on disk; a file whose region is empty yields status `NO-PROSE` and exit 0, never an error.
  - STATED LIMITATIONS, the same category as one another, none an oversight: (1) a 4-space-indented block is NOT a code block for this purpose; (2) a code span that WRAPS across a line break is left in the region, content and all, because pairing backticks in the presence of a stray one is not decidable from a single document, and every version that tried to delete wrapped spans mispaired a stray and ate real prose between two backticks (three review Criticals). Same-line-only extraction makes eating prose across a line break structurally impossible, at the cost that a wrapped span's content is counted. That content is code, almost never a function word in any of the four lists, so it does not move the verdict; this reverses the round-2 decision to delete wrapped spans, deliberately. A second, bounded cost: on ONE line whose backticks do not pair cleanly (a stray plus a real span), that line's prose between them is deleted; the loss is confined to a single line and cannot silence a document-level verdict. Both are pinned as cases (K10, K12b for the first; K15c, K15d for the second) rather than left as prose.

### C2: the function-word lists
- Kind: four closed data lists inside `bin/prose-language-check.sh` (space-separated shell strings, the house convention of `VALID="en de hr fr"`)
- Declaration: four ASCII-only, lowercase, space-separated lists, each held in a variable named `WORDS_<CODE>` whose assignment occupies exactly ONE physical line:
  - `WORDS_DE` (69): `aber alle auch auf aus bei beim dabei damit dann das dass dazu dem den der die durch ein eine einem einen einer es gegen ihre ihrem ihren im immer ist jede jeder jedes kann kein keine mehr mit muss nach nicht noch nur oder ohne schon sehr seine seinen sich sie sind und uns unter vom von weil wenn werden wie wir wird wurde zu zum zur zwischen`
  - `WORDS_EN` (64): `about after against all and any are as at be because been before between but by can could each every for from had has have here if into is it its more must not of only or out over should some such than that the their them then there these this those through under very we were when which while with without would you`
  - `WORDS_FR` (53): `alors au aussi aux avec ce cela ces cette chez comme dans doit dont elle elles encore entre est et faut il ils la le les leur leurs lorsque mais nous ont ou par pas peut pour quand que qui sera ses son sont sous sur tous tout toute toutes un une vous`
  - `WORDS_HR` (55): `ako ali bez bi bila bilo bio biti da gdje ili iz jedan jedna jer kad kada kao koja koje koji kroz mi na nakon nam nas nije nisu njih ona oni ono ova ovaj ovo po pod prije prema preko sam samo smo ste su sve svaki svi ta taj te vi za zato`
  and one EXCLUSION SET that must appear in no list, per design decision 6: every single-character token (`a i o u y`); the German/English homographs `an in so am was also will man hat war bin`; the German/French homographs `des du`; the French/Croatian homographs `je se ne si sa`; the English/Croatian homographs `to do on no`; the four language codes `de en fr hr`; and the English structural-label interrogatives `what why how where who`. The exclusion set is a literal in the TEST ONLY and never in the script: it is an anti-list, the script has no use for it, and an independent literal is what makes group H a check rather than a tautology.
- Produced by: Task 2
- Consumed by: Task 3
- Invariants: each `WORDS_*` assignment has exactly ONE physical line and exactly one site in the script, so the suite can extract it by line without sourcing the script (which would run its argument parsing and exit 2); the four lists are pairwise DISJOINT (all six pairs); every entry matches `^[a-z][a-z]+$`; no entry appears twice within a list; no member of the exclusion set appears in any list; each list holds at least 50 entries, so nobody can gut one silently. A token contributes at most one hit, to at most one language, and hits are counted per OCCURRENCE, not per distinct word.

### C3: the report grammar and the exit contract
- Kind: stdout/stderr format + exit contract
- Declaration: `prose-language-check.sh <project-dir> <file> [<file>...]` emits, for each file in argument order, one FIELD LINE of exactly this shape:
  `prose-language: <STATUS> <path> expected=<code> detected=<code|none> counted=<n> de=<n> en=<n> fr=<n> hr=<n>`
  with `<STATUS>` in `WARN | OK | LOW-EVIDENCE | NO-PROSE | UNREADABLE`, the four counts always present in that fixed order, `<code>` always one of `en de hr fr`, and `detected=none` only when `counted=0`. `UNREADABLE` was added after v1 (round 3 of review): it splits C4's `counted == 0` case so a region that is non-empty but yields no countable token (a non-Latin script, or legible Latin prose holding none of the four lists' function words) is told apart from a genuinely empty region, which stays `NO-PROSE`. It carries no language knowledge and never warns, because with lists for `en de hr fr` only the check can report that it could not read the region, never that the language is wrong. `detected` is the code with the most hits, ties broken alphabetically so the output is deterministic. For `WARN` only, a SECOND, plain-language line follows:
  `prose-language: warning only, nothing is blocked. <path> reads as <detected> while this project is set to <expected>.`
  Both `WARN` lines go to STDERR; `OK`, `LOW-EVIDENCE` and `NO-PROSE` lines go to STDOUT. After all files, one summary line on STDOUT:
  `prose-language: <n> file(s) checked, <w> warning(s); warnings never fail, exit 0.`

### C4: the warning decision rule
- Kind: behavior rule (two named constants plus one comparison)
- Declaration: let `target` be the hit count for `expected`, `counted` the sum of all four counts, `rival` the highest count among the three codes other than `expected`, and `rival_code` its code (alphabetical tie-break). With `MIN_HITS=12`:
  - `counted == 0` and the surviving region has no non-whitespace character -> status `NO-PROSE`, no warning.
  - `counted == 0` and the region is non-empty (a script none of the four lists can read) -> status `UNREADABLE`, no warning. (Added round 3; see C3.)
  - `counted < MIN_HITS` -> status `LOW-EVIDENCE`, no warning, whatever the ratio is.
  - `rival * 2 > counted` -> status `WARN`, `detected=<rival_code>`.
  - otherwise -> status `OK`.
  "More than half" is STRICT: `rival * 2 > counted`, so an exact half is `OK`. `MIN_HITS` has exactly one assignment site in the script.
- Produced by: Task 2
- Consumed by: Task 3, Task 4
- Invariants: the two clauses (`rival` majority AND `counted >= MIN_HITS`) are independent and each gets a test case where ONLY that clause is violated (Task 2 cases F2 and F3), plus a strictness pair at exactly `counted=12` (F4a `rival=6` -> `OK`, F4b `rival=7` -> `WARN`) and an inclusivity case (`counted=12`, `rival=12` -> `WARN`, proving the minimum is `>=` and not `>`); `target` never enters the comparison directly, so a document with zero German hits and 11 English hits is `LOW-EVIDENCE`, not `WARN`.

## Risks / open questions

1. **This is a heuristic and the plan calls it one everywhere.** It will warn on documents that are legitimately multilingual: an English-on-purpose fixture story, a long English quotation inside a German memo, or a very short German plan whose English-by-rule commit subjects and verify lines are a large share of its prose region. Mitigations are structural: seven exclusions keep headings, tables, fences, code spans, link targets and URLs out of the region; the threshold is a strict majority; the 12-hit minimum keeps very short documents silent. What remains is accepted noise on a check that blocks nothing.
2. **Nothing invokes it automatically.** G2 defers the wiring to its own story. The consequence, stated plainly: a PM who never runs it never sees a warning, so PRD-001 R7 is covered only in its mechanism half by this story. The follow-up is five files and five review records.
3. **The word lists are a judgment artifact and their correctness rests on the disjointness rule, not on anyone's vocabulary.** Group H enforces pairwise disjointness, the shape rule, the minimum size, the exclusion set and the one-site property mechanically. Adding a fifth language later means a new list AND re-running that check; a token that turns out ambiguous is removed from every list, never assigned to one. Floor policy, stated because FR sits three above it: a removal that would breach the 50-entry floor ships with a replacement token in the same commit, or the floor moves with a recorded reason, so nobody is ever under pressure to invent function words.
4. **Named homograph residue, which the machine check cannot see.** Seven lower-frequency cross-language homographs stay in the lists on purpose (decision 6): `im`, `te`, `ta`, `but`, `or`, `die`, `den`. Cost is a few hits per document, not a flipped verdict. Unenforceable by construction, since there is no mechanical oracle here for "this token is also a word in another language", so it is written down instead of guarded.
5. **One mandated English label leaks exactly one English hit per finding, measured.** `agents/architecture-reviewer.md:96` mandates `**Why it matters:**`, and while `why` is in the exclusion set, `it` IS in `WORDS_EN` and `matters` is in no list, so a German review write-up scores ONE English hit per finding from a label USR-005 forces to be English. v1 claimed the mandated labels give a German review no English hits, which was wrong. Arithmetic for why it is recorded rather than fixed: a six-finding German review scores 6 English hits against a German prose body of easily 60 or more, so `12 > 66` is false and no false warning results. `it` is not excluded because it is one of the highest-signal English function words and losing it would cost exactly the English detection AC1 depends on. The exact follow-up if this ever matters: an eighth exclusion deleting a leading `**...:**` bold run at the start of a line or list item, the same class of reason the heading exclusion rests on. Not built now, per YAGNI and the arithmetic.
6. **The HR list is structurally the weakest, and the uniform threshold hides it.** The exclusion set removes `je se i a u o to do on no ne si sa` from Croatian, which is most of its highest-frequency tokens, while German keeps `der die das und ist` and English keeps `the of and is that for`. With one `MIN_HITS=12` for all four, short Croatian documents land in `LOW-EVIDENCE` more often than short German ones. This is a property of the design, not of the testing, and it is stated so nobody reads uniform thresholds as uniform sensitivity.
7. **`fr` and `hr` get one case each, and that is honestly thin.** Group E proves each list produces its own `detected=` code on real prose in that language, which proves the list is wired and not empty. Nobody has measured accuracy on French or Croatian documents at length, and this plan does not claim it.
8. **`MIN_HITS=12` and the strict-majority rule are judgment numbers, and both get a second statement site.** Both are named constants with one asserted site each in the script, and both are also stated in `AGENTS.md` prose, which is drift-prone: nothing checks that the digits in the bullet still match the constants. Accepted deliberately, and the reason is BLAST RADIUS rather than cheapness: a stale script NAME misdirects an action that sixteen surfaces will attempt, which is Task 5's entire premise, while a stale THRESHOLD misdescribes a verdict that blocks nothing. The reviewer noted this is the one residue in this plan that DOES have a mechanical oracle, since group H already extracts `^MIN_HITS=` and Task 4's verify already extracts section 7, so a cross-site agreement assertion would be two lines. Not taken now, and the choice is recorded rather than left as an omission. The plan does not pretend either number was derived from data.
9. **G3 is a correction to shipped work, and the lesson in it is worth more than the fix.** `PRD-901`'s German section headings violated a rule the same story shipped, and the reason nothing caught it is that the rule is `[I]`: a heading is not a machine surface, so the `[E]` guard cannot see it, and three rounds of code review, a live check and the executor's own verification all passed it. That is what `[I]` costs, measured on our own artifact within a day of shipping. If the human ever wants this class enforced, the mechanism would be a check over GENERATED documents, which is exactly the shape this story builds, and extending it to "structural labels are English" is a plausible next story rather than a change here.
10. **Instrument discipline is load-bearing for whoever re-verifies decision 14.** An inline `$'...'` byte-class pattern passed through a tool command layer can arrive mangled and then silently match nothing, which produced two false findings during this plan's own gate: a claimed grep portability defect that does not exist, and a claimed absence of non-ASCII outside the headings that was wrong. Both were caught by planting a positive control, and both had already been spoken. Run these probes from a script file.
11. **Known mechanism limits, written now so nobody finds them later and calls them defects.** A 4-space-indented block is prose to this check. A pipe table written WITHOUT a leading pipe is counted as prose, because step 5 keys on the first non-whitespace character. A word carrying a diacritic is split into fragments and effectively ignored, and an ALL-CAPS diacritic word is missed. Croatian `šest` tokenizes to `est`, which is in `WORDS_FR`, and the same shape recurs for other words whose first syllable is a diacritic. A hyphenated or multi-word English phrase in German prose contributes English hits (decision 5 lists six measured examples).
